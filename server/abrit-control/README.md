# پنل و بستهٔ انتقال abritdesk

این سرویس مستقل از سرور اتصال است. رمز root، SSH، کلیدهای هویت سرور اتصال و DNS را تغییر نمی‌دهد.

## استفادهٔ مدیر

آدرس نهایی پنل: `https://serverdesk.abrit.cloud/admin`.
تا تکمیل مسیر HTTPS عمومی، پنل داخل شبکه با `https://10.0.0.150/admin` قابل دسترسی است. گواهی مستقیم IP فعلاً محلی و خودامضاست؛ برای استفادهٔ نهایی عمومی باید گواهی معتبر روی مسیر دامنه فعال باشد. کلاینت اعتبار TLS را بررسی می‌کند و این بررسی خاموش نمی‌شود.

حساب پنل `manager` از SSH جداست. اطلاعات ورود اولیه در `/root/abrit-control-access.txt` با دسترسی فقط root نگهداری می‌شود؛ این فایل را در مسیر عمومی، GitHub یا برای حساب SSH استفاده نکنید. پس از تغییر رمز از بخش «حساب پنل»، فایل ورود اولیه ممکن است دیگر رمز فعلی را نشان ندهد.

- «بنر برنامه»: بارگذاری تصویر اصلی و تصویر اختیاری تیره، عنوان و توضیح فارسی/انگلیسی، لینک مقصد یا مخفی‌کردن بنر.
- پیش‌نمایش قبل از ذخیره تغییر می‌کند؛ با «ذخیره و انتشار» revision و ETag خودکار تغییر می‌کنند. مقدار پیش‌فرض تازه‌سازی ۳۰ ثانیه است.
- «نسخه و بروزرسانی»: حالت اختیاری، حداقل نسخه یا اجبار همهٔ نسخه‌های پایین‌تر از latest. ابتدا لینک دانلود واقعی را منتشر کنید. انتشار الزام به تأیید صریح مدیر نیاز دارد.
- «تاریخچه»: نمایش موارد تغییرکردهٔ هر انتشار با برچسب‌های فارسی، مثل آخرین نسخه، حداقل نسخه و تصویر بنر؛ هر صفحه ۱۰ مورد از جدیدترین به قدیمی‌ترین نشان می‌دهد و دکمه‌های جدیدتر/قدیمی‌تر به بقیهٔ سوابق می‌رسند. بازگردانی هر انتشار قبلی با revision جدید انجام می‌شود؛ سوابق و تصاویر قبلی حذف نمی‌شوند.
- «حساب پنل»: تغییر فقط رمز پنل. نشست‌های دیگر پنل با تغییر رمز باطل می‌شوند؛ SSH تغییری نمی‌کند.

حداقل نسخهٔ اولیه `0.0.0` و اجبار خاموش است؛ راه‌اندازی سرویس کاربران را مجبور به بروزرسانی نمی‌کند. بیلد دارای API این دامنه از نسخهٔ 1.5.2 عرضه می‌شود؛ پیش‌نمایش 1.5.1 قبلی به endpoint پیشنهادی دیگری اشاره می‌کرد. کلاینت‌های قدیمی فاقد API با این پنل مسدود نمی‌شوند.

## مسیرهای ثابت

| مسیر | محتوا |
| --- | --- |
| `/opt/abrit-control` | کد، فونت/لوگو، اسکریپت‌ها و wheelهای وابستگی؛ محیط Python در `.venv` دوباره ساخته می‌شود |
| `/etc/abrit-control/config.json` | دامنهٔ ثابت، کلید نشست پنل و مسیر داده‌ها؛ خصوصی |
| `/etc/abrit-control/tls` | گواهی و کلید TLS مبدا |
| `/var/lib/abrit-control` | دیتابیس حساب پنل، سیاست، تاریخچه و تصاویر |
| `/var/lib/rustdesk-server` | کلیدهای اصلی هویت و دیتابیس سرور اتصال موجود |
| `/srv/abritdesk-transfer` | بسته‌های انتقال خصوصی؛ خارج از وب |

API عمومی `GET /api/v1/client/windows` است؛ مدیریت فقط از مسیر `/admin` و پس از ورود انجام می‌شود. Gunicorn روی loopback `127.0.0.1:8088` و nginx روی ۸۰/۴۴۳ اجرا می‌شوند. تنظیمات و فایل‌های سرویس‌های اتصال موجود تغییر نمی‌کنند.

## ایجاد بستهٔ انتقال کامل، بدون توقف سرویس

با SSH و حساب مالک سرور:

```sh
python3 /opt/abrit-control/deploy/backup.py
```

فایل `abritdesk-transfer-<time>.tar.gz` و فایل SHA256 کنار آن در `/srv/abritdesk-transfer` ساخته می‌شوند. بسته شامل برنامه و وابستگی‌های Python، تصاویر، تاریخچه و حساب‌ها، secret نشست پنل، گواهی مبدا، **کلید خصوصی و عمومی اصلی سرور اتصال**، دیتابیس و فایل اجرایی دقیق hbbs/hbbr و تنظیمات سرویس‌هاست. دیتابیس‌ها با API backup خود SQLite به‌شکل سازگار کپی می‌شوند؛ فایل‌های WAL فعال کورکورانه کپی نمی‌شوند و اتصال‌ها متوقف نمی‌شوند.

بسته محرمانه است و نباید در Release گیتهاب، هاست عمومی یا به مدیر محتوا داده شود. آن را با SFTP/SCP مالک منتقل کنید. حساب‌ها و شبکهٔ سیستم‌عامل، رمز root و کلیدهای SSH سیستم در بسته نیستند؛ ورود و شبکهٔ سرور جدید متعلق به خود آن سرور می‌مانند.

## بازیابی روی سرور جدید

مبنای این بسته Ubuntu 24.04 x86_64 است. یک سرور **تازه** با دسترسی SSH مستقل آماده کنید. تغییر معماری/سیستم‌عامل به نصب و بررسی جدا نیاز دارد. نصب پیش‌نیازهای سیستم‌عامل nginx و Python venv ممکن است به مخزن Ubuntu نیاز داشته باشد؛ کتابخانه‌های خود برنامه داخل بسته هستند و به PyPI نیاز ندارند.

قبل از انتقال نهایی، بستهٔ تازه بسازید و SHA256 را با فایل همراهش مقایسه کنید. فایل‌ها را در پوشهٔ خصوصی استخراج کنید:

```sh
sha256sum -c abritdesk-transfer-<time>.tar.gz.sha256
mkdir -m 700 /root/abritdesk-restore
tar -xzf abritdesk-transfer-<time>.tar.gz -C /root/abritdesk-restore
python3 /root/abritdesk-restore/restore.py /root/abritdesk-restore
python3 /root/abritdesk-restore/restore.py /root/abritdesk-restore --restore
```

دستور اول Python فقط یکپارچگی همهٔ فایل‌ها، دیتابیس‌ها و هویت سرور را بررسی می‌کند. `--restore` فقط روی سرور تازه اجرا می‌شود؛ وجود پوشه‌های برنامه یا سرویس فعال باعث رد بازیابی می‌شود تا چیزی بازنویسی نشود. کد و داده‌ها در همان مسیرهای ثابت قرار می‌گیرند، محیط Python دوباره ساخته می‌شود و همان کلیدهای سرور و حساب پنل بازیابی می‌شوند. برنامهٔ Windows به‌خاطر جابه‌جایی سرور، به بیلد جدید نیاز ندارد چون دامنه ثابت می‌ماند.

قبل از تغییر DNS، با مسیر آزمایشی دامنه به سرور جدید، ورود پنل، API، گواهی، بنر، به‌روزرسانی و اتصال دو کلاینت را بررسی کنید. سپس ترافیک/ورودی جدید را برای انتقال نهایی هماهنگ کنید، آخرین snapshot را منتقل کنید و DNS و NAT/Reverse Proxy موردنیاز را به سرور جدید هدایت کنید. نشست‌های فعال روی سرور قدیمی با تغییر DNS به سرور جدید منتقل نمی‌شوند؛ باید دوباره متصل شوند. رمزهای دستگاه‌ها و تنظیمات محلی کاربران در این بسته قرار ندارند و جابه‌جایی سرور آن‌ها را تغییر نمی‌دهد.

سرور قدیمی و بستهٔ قبلی را تا تأیید سرور جدید نگه دارید. در صورت مشکل، مقصد DNS/Proxy را برگردانید؛ کلیدهای یکسان باعث می‌شوند تنظیمات ثابت کلاینت معتبر بمانند. اگر پس از انتقال دادهٔ جدیدی روی سرور تازه ایجاد شده باشد، قبل از بازگشت باید همگام‌سازی آن بررسی شود.

بیلد 1.5.2 اتصال بیکار API را برای نوبت بعد نگه نمی‌دارد تا درخواست تازه مقصد دامنه را دوباره resolve کند. انتشار DNS همچنان به TTL و کش resolver وابسته است. پس از هدایت ترافیک و پایان مهلت انتشار DNS، سرویس‌های قدیمی را در زمان انتقال هماهنگ‌شده از مدار خارج کنید؛ اگر Reverse Proxy جلوی API قرار دارد، اتصال‌های قدیمی آن هم باید بسته شوند. نگه‌داشتن فایل‌ها و تنظیمات قدیمی برای بازگشت، به معنی فعال‌ماندن هم‌زمان دو سرور مستقل نیست.

## نگهداری مالک

```sh
systemctl status abrit-control nginx rustdesk-hbbs rustdesk-hbbr
journalctl -u abrit-control -n 80 --no-pager
ABRIT_CONTROL_CONFIG=/etc/abrit-control/config.json /opt/abrit-control/.venv/bin/python /opt/abrit-control/app.py reset-password --username manager
```

دستور آخر فقط رمز پنل را با ورودی تعاملی عوض می‌کند؛ رمز SSH را تغییر نمی‌دهد. برای حذف سرویس جدید، فقط `abrit-control` را stop/disable و دو symlink مربوط به `abrit-control-*` را از nginx حذف و پس از `nginx -t` reload کنید؛ سرویس‌های hbbs/hbbr را متوقف نکنید. پوشهٔ داده‌ها را برای بازگشت نگه دارید.

## آزمون‌ها و محدودیت بررسی

`python -m unittest -v test_app` ورود، CSRF، هدرها، محدودیت تلاش ورود، نسخه‌ها، انتشار زنده و ETag/304، تأیید اجبار، حفظ سیاست معتبر هنگام ورودی خراب، تداخل ویرایش، تصویر امن، بازگردانی و ابطال نشست بعد از تغییر رمز را بررسی می‌کند. پنل با مرورگر در عرض‌های ۱۴۴۰، ۹۶۰، ۶۸۰ و ۳۹۰ و پیش‌نمایش فارسی/انگلیسی بررسی می‌شود.

یکپارچگی بسته و snapshotها قابل آزمون روی سرور فعلی است؛ بازیابی واقعی روی سرور تازه و تغییر DNS باید هنگام مهاجرت و پیش از انتقال کاربران آزمایش شوند. فایل‌های قبلی سرور اتصال و SSH با هش قبل/بعد مقایسه می‌شوند و سرویس‌های اتصال بدون restart باقی می‌مانند.

## سطح تغییرات

پیاده‌سازی سرور در پوشهٔ جدید و مستقل قرار دارد. تغییرهای موجود در مخزن کلاینت فقط آدرس API و فیلتر اجرای بیلد در workflow، افزایش نسخه برای تمایز endpoint صحیح، اسناد و یک تنظیم در `src/abrit_policy/runtime.rs` هستند؛ تنظیم جدید اتصال بیکار API را نگه نمی‌دارد تا انتقال DNS در بررسی بعدی دیده شود. مسیر اتصال اصلی و UI این مرحله بازنویسی نشده‌اند. روی میزبان فقط حساب سرویس بدون shell، nginx، Python venv، سرویس `abrit-control`، پیکربندی و پوشه‌های خصوصی جدید اضافه می‌شوند. رمزها، SSH، DNS، firewall و فایل‌ها و فرایندهای سرور اتصال موجود تغییر نمی‌کنند.
